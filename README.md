# Scholarship Intelligence Crawler

A local, repeatable scholarship discovery and verification application for Indian students. Uses Python, Requests, BeautifulSoup, SQLite and Streamlit. No paid API or hosted scraping service is used.

## What is implemented

- Seed-source crawling across NSP, UGC, AICTE, Ministry of Education, Ministry of Tribal Affairs and Social Justice & Empowerment.
- Open-web discovery through DuckDuckGo HTML results; discovery URLs are accepted only when the domain passes the official-domain allowlist.
- Rule-based extraction of scholarship headings and directly visible dates.
- A universal SQLite record with eligibility, amount, education level, income, age, gender, category, domicile, institution, documents, selection, renewal and status fields.
- Missing values are stored as `Not specified`; the crawler does not infer missing eligibility or award amounts.
- Evidence snippets are retained with source URL and field name.
- Deterministic confidence scoring (not generated by an LLM).
- SQLite snapshots and field-level change history.
- Expiry status from the observed closing date; missing-on-two-consecutive-runs becomes `NO_LONGER_VERIFIABLE`.
- Searchable Streamlit dashboard and daily scheduler.

## Run locally

Python 3.10+ recommended.

```bash
# Windows PowerShell
py -m venv .venv
.venv\\Scripts\\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

Open the local URL shown by Streamlit.

## Run crawler

```bash
python -m src.run_crawler
```

## Run automatically every 24 hours

```bash
python scheduler.py
```

Keep that process running. The scheduler performs one crawl immediately and then repeats every 24 hours.

## Database

SQLite file: `data/scholarships.db`

Tables:
- `scholarships`: current normalized record
- `evidence_json`: field-to-source evidence
- `snapshots`: every stored crawl snapshot
- `changes`: old value, new value, detection time, source and evidence
- `crawl_runs`: run counts and logs
- `sources`: crawled source registry

The database is created automatically on first launch. `data/sample_records.json` is a dated sample snapshot taken from the official NSP Academic Year 2026-27 list. It is not represented as a live crawl. Use **Run crawler now** to refresh from the web.

## Confidence score

The score is deterministic and uses observed evidence:

| Signal | Points |
|---|---:|
| Official-domain allowlist | 30 |
| Exact scholarship title present on fetched page | 20 |
| Provider evidence present | 10 |
| Official application route | 10 |
| Closing date appears in fetched page | 10 |
| Opening date appears in fetched page | 5 |
| Three or more evidence entries retained | 10 |
| Successful fresh fetch | 5 |
| **Total** | **100** |

`VERIFIED` is assigned only at 95 or above. Otherwise the record is `REVIEW REQUIRED`. The score measures source-backed identity/current listing evidence, not whether every optional field is populated. An unknown field remains `Not specified`.

## Change and stale detection

When the same scholarship is observed again, changed fields are written to `changes` before the current row is updated. The old and new values, timestamp, source URL and evidence are retained. A record not seen in one run becomes `REVIEW_REQUIRED`; after two consecutive missed runs it becomes `NO_LONGER_VERIFIABLE`. A closing date in the past becomes `EXPIRED`.

## Discovery and source classification

Seed URLs are starting points only. Each crawl also runs general scholarship queries against DuckDuckGo's public HTML search page. Search results are discovery candidates only. A URL is crawled only if it belongs to a government, regulator, university or explicitly allowlisted official provider domain. Aggregator results are not used as verification sources.

## Known limits

- Many official portals render details with JavaScript, CAPTCHA, session tokens or PDFs. Such pages may require source-specific adapters; this crawler does not fabricate missing fields when it cannot parse them.
- Generic page extraction is intentionally conservative. The NSP listing adapter extracts visible scheme headings and adjacent dates. For sources whose official pages do not expose a reliable structured detail page, records remain review-required.
- Search-engine availability and website HTML changes can affect discovery. The database and evidence log expose crawl failures rather than silently treating them as verified.
- Sample snapshot data is from the official NSP list fetched 6 November 2026. It is a reproducible starting snapshot; the live crawl is the authoritative refresh operation.

## Technical note

1. **Discovery:** crawl configured official seed portals, then discover additional official URLs through scholarship-focused public search queries. Search is not treated as evidence.
2. **Classification:** classify URLs by official host and known provider domain. Aggregators are rejected as authoritative sources.
3. **Extraction:** parse headings and local text context; extract only visible dates and provider context. All unobserved fields remain `Not specified`.
4. **Verification:** verify domain, title presence, provider, application route, date evidence, evidence traceability and successful current fetch.
5. **Confidence:** weighted deterministic rubric in `src/verify.py`; no LLM confidence generation.
6. **Anti-hallucination:** no LLM is used to fill fields. Evidence snippets and URLs are stored alongside extracted values.
7. **Persistence/change detection:** SQLite stores current rows, immutable crawl snapshots and field-level changes. Missed records are moved through review to no-longer-verifiable.
8. **Interface/automation:** Streamlit dashboard runs crawls on demand; `scheduler.py` repeats every 24 hours.
